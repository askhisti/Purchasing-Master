# MasterData tabs: contract notes (phase 1)

Source of truth for headers is `sql/feeds.json`; SQL is in `sql/feeds/*.sql` (first column `ROW_KEY`, then manifest columns in order, then `DEMAND_<year>` for each demand year where applicable). Placeholders: `{{BASE_YEAR}}`, and `{{DEMAND: <template>}}`, which expands to one line per demand year with `#YEAR#` replaced (the template starts with a comma). Demand years run from the fixed `firstYear` 2025 (the first year with demand in Snowflake) to BASE_YEAR+10, so each January appends one column and none is ever removed. Demand headers are `Demand <year>`, appended after the listed columns. A feed may set `demandYears.headerPrefix` (default `"Demand "`, e.g. `"Units "`) to change that header prefix. A feed may also carry `demandMonths: {sqlPrefix, yearsAhead}` (and then must have `demandYears`): months exist only for BASE_YEAR through BASE_YEAR+`yearsAhead` (feeds use 1, so 24 months), SQL names `<sqlPrefix><year>_<MM>`, headers `YYYY-MM`, type number. Each year's months sit directly before that year's total, so the layout is `Demand 2025, 2026-01..2026-12, Demand 2026, 2027-01..2027-12, Demand 2027, Demand 2028, ...`; each January the first year's months drop out and the next year's twelve months appear. `{{SERIES: <year template> || <month template>}}` expands to exactly that order (one line per year with `#YEAR#`, one per window month with `#YEAR#`, `#MONTH#` (1-12), `#MM#` (01-12)), so the SELECT order equals the manifest order that the CLI checks. `{{MONTHS: <template>}}` expands months only (same placeholders), for CTEs; like DEMAND, a template without `#YEAR#` or with nothing to expand is an error. Every feed's rendered SQL stays at or below 8,000 characters (test/feeds-sql.test.mjs). `node scripts/feed-check-sql.mjs <feed> [baseYear]` prints the count SQL and a 3-row sample SQL separated by `-- next`. Health gate: `sql/health.sql`.

## Step 1 facts (verified against Snowflake on 2026-10-30)

- `COMPONENT_CATALOG.SUPPLIER_PARTNUMBER` holds the `ME_EC_...` number (2,510 `ME_EC_` rows plus 247 `ME_MC_` rows; 2,757 rows, all keys distinct and non-null). `COMPONENT_ID` is the numeric id used by joins.
- `PART_ID` in `KPI_COMPONENT_DEMAND_BY_YEAR` and `COMPONENT_DEMAND_FORECAST` is a mixed id space (`PART_KIND` = COMPONENT, BOUGHT_ITEM, SUB_ASSEMBLY); all joins to the catalog filter `PART_KIND = 'COMPONENT'` so ids cannot collide.
- `PLATFORM_HEALTH.AREA` values: `BASELINE`, `JIRA_PROJECT`, `MECL_SNAPSHOT`, `SAP_ENTITY`, `TASK`. All rows were `IS_PROBLEM = false` at check time. The gate (R34) blocks on `IS_PROBLEM` rows with `AREA = 'MECL_SNAPSHOT'` or whose `OBJECT_NAME` is `TASK_REFRESH_PURCHASING`, `TASK_REFRESH_SUPPLY_CHAIN` or `TASK_REFRESH_PLATFORM_HEALTH`; feed view names never appear in `PLATFORM_HEALTH`, so they are not part of the gate.
- `PRODUCT_CATALOG.PRODUCT_SAMPLE_PHASE` holds values such as `Series`, `C2-Sample`, `A1-Sample`; `START_OF_PRODUCTION` is a DATE (some NULL). Names match content.
- `MULTISOURCE_PARTS.USABLE_MEMBERS` is a count (number), not a list.
- Only `COMPONENT_WHERE_USED` and `SC_EMS_PART` carry `REFRESHED_AT`, so `health.sql` returns `REFRESHED_AT_SC_EMS_PART` and `REFRESHED_AT_COMPONENT_WHERE_USED` only.
- Builder's calls: `Description` = `CORE_DESCRIPTION`, else `HW_DESCRIPTION`; `Lifecycle` = `HW_LIFECYCLE`, else `SE_LIFECYCLE` (HW populated for 666 of 2,757, SE for 2,510); `Years To EOL` = `YEARS_TO_END_OF_LIFE`.

## Components
Key `ME_EC`. Sources `COMPONENT_CATALOG`, `KPI_COMPONENT_DEMAND_BY_YEAR`, `MULTISOURCE_PART_MEMBERS`, `SC_EMS_PART`, and `COMPONENT_DEMAND_FORECAST` for the months. Columns: ME_EC (string), Manufacturer (string), MPN (string), Description (string), HW Category (string), HW Subcategory (string), Component Status (string), Lifecycle (string), Years To EOL (number), ME_MS (string; all usable clusters, comma-separated), Primary ME_MS (string; highest-numbered usable cluster), EMS Part Numbers (string; `EMS:part`, latest snapshot, comma-separated), Is Sourced By Us (boolean), then the rolling series `Demand 2025`, `2026-01`..`2026-12`, `Demand 2026`, `2027-01`..`2027-12`, `Demand 2027`, `Demand 2028`..`Demand Y+10` for Y = 2026 (numbers). Months exist only for the current and next year (24 columns); each year's months sit before its total. Yearly cells are `TOTAL_DEMAND` of sourced-by-us rows from `KPI_COMPONENT_DEMAND_BY_YEAR`, 0 when none. Month cells are `SUM(DEMAND_QUANTITY)` from `COMPONENT_DEMAND_FORECAST` (`IS_SOURCED_BY_US AND PART_KIND = 'COMPONENT'`, joined on `PART_ID = COMPONENT_ID`, month `TO_CHAR(MONTH_START,'YYYY-MM')`), rounded to `NUMBER(38,2)`, 0 when there is no plan; they sum to the yearly demand exactly. Each January the previous year's months drop out and the new next year's twelve months appear; yearly columns stay. Note on A1. Live check 2026-11-04: 2,777 rows, unique keys, 50 columns; all parts 2026 = 452,552,625 and 2027 = 873,963,259 both as months and yearly.

## Multisource
Key `ME_MS`. Sources `MULTISOURCE_PARTS` plus member demand. Columns: ME_MS, Sourcing Health (string), Member Count, Usable Member Count, Manufacturer Count (numbers), Demand 2025..Y+10 (sum over that cluster's own usable members only; never across clusters sharing a member).

## Multisource_Members
Key `ME_MS|ME_EC`. Source `MULTISOURCE_PART_MEMBERS`, all member statuses. Columns: ME_MS, ME_EC, Member Status (strings), Is Usable (boolean), Member Priority (number), Manufacturer, MPN (strings).

## Component_Usage
Key `ME_EC|PRODUCT_ID`. Sources `COMPONENT_DEMAND_FORECAST` (sourced by us, pivoted by `DEMAND_YEAR`, `DEMAND_QUANTITY`), `COMPONENT_WHERE_USED` (Project). Columns: ME_EC, MPN, Manufacturer, Product, Product ID (number), Project, Program, Customer, EMS (strings), Qty Per Unit (number, `QTY_PER_UNIT`), Demand 2025..Y+10 (number, per product).

## Products
Key `PRODUCT_ID`. Source `PRODUCT_CATALOG`. Columns: Product ID (number), Product Display Name, Project, Program, Customer (strings), Sample Phase (`PRODUCT_SAMPLE_PHASE`), EMS, SOP (date `YYYY-MM-DD`, `START_OF_PRODUCTION`), Is Hierarchy Active (boolean).

## MECL_Price
Key `COMPONENT_PRICE_ID|COALESCE(PART_NUMBER,'')` (a quote linked to two components appears twice). Source `COMPONENT_PRICE_ITEMS` (plus `COMPONENT_CATALOG` for resolution). Columns: Price ID (number), ME_EC, Resolved ME_EC (`PART_NUMBER` if linked, else the single catalog component whose trimmed upper-cased MPN equals the trimmed upper-cased quoted MPN, else blank), Is Linked (boolean), Price Type, Price Owner, Vendor, Vendor Part Number, Volume Stage (strings), Year (number), MOQ (number), Price (number, quoted currency), Currency, Price EUR (current rate) (number), Quoted Unit, Quoted Manufacturer, Quoted MPN, Quote Reference, Quote File (strings), Valid From, Valid Until (dates), Is Valid Today, Is Binding (booleans), Created At (date).

## Product_Volumes
Key `PRODUCT_ID|Flow`. Sources `COMPONENT_DEMAND_FORECAST` (all rows, no sourced or part-kind filter; `MAX(PLANNED_PRODUCT_UNITS)` per product, flow and month because product units repeat on every part row), `PRODUCT_CATALOG` (Project; blank when the product is not in the catalog). Columns: Product ID (number), Product Display Name, Project, Program, Customer, EMS, Flow (strings; Flow is `Series` or `Sample`), the rolling series `Units 2025`, `2026-01`..`2026-12`, `Units 2026`, `2027-01`..`2027-12`, `Units 2027`, `Units 2028`..`Units Y+10` for Y = 2026 (number; each year's months sit before its total; months only for the current and next year; planned units, 0 when no plan; a yearly cell is the sum of that year's months over all months, not only the window). Year and month cells are rounded to 2 decimals (`NUMBER(38,2)`) after summing. Page limit 200. Live check 2026-11-04: 56 rows, 44 columns, months equal Units (2026: 937,252; 2027: 1,969,617).

## BOM_Coverage
Key `Year` (`TO_VARCHAR(PLAN_YEAR)`). One row per plan year. Source `PRODUCT_DEMAND_BASIS`. Columns (all numbers): Year, Planned Units (`SUM(PLANNED_UNITS)`), Released BOM Units (`PLANNED_UNITS` where `DEMAND_BASIS = 'RELEASED_BOM'`), Released BOM Share % (`100 * released / NULLIF(planned, 0)`, 1 decimal; weighted by units). The demand tabs' header notes point here. Page limit 100. Live: 2026 share 83.5.

## Manufacturer file
Menu `MasterData` > `Create manufacturer file...` (bound script, `MfrFile.ts` and `MfrDialog.html`; needs the scope `script.container.ui`). The dialog takes a manufacturer name, an "Only parts we use" switch (parts that are the ME_EC of a `Component_Usage` row, or a usable alternative of one in `Multisource_Members`) and a category / subcategory tree with counts of distinct parts. `createManufacturerFile` reads `Components`, `Component_Usage`, `Multisource_Members` and `Product_Volumes`, takes the base year from `_Refresh_Log` B2 (current Berlin year when it is not an integer) and creates a new spreadsheet `<manufacturer> - component overview - <yyyy-MM-dd>` in `03_Master File from Snowflake/Manufacturer files` (folder created when missing). A line is one `Component_Usage` row (ME_EC x Product ID; position 1 = that ME_EC, Volume Type `Demand`, `Volume Y`..`Volume Y+10` = its `Demand <year>` columns). Its alternatives are the `Multisource_Members` rows with `Is Usable` true in every cluster (ME_MS) that has the primary as a member (any status), primary excluded, one row per alternative (lowest `Member Priority`, ties lowest ME_MS, which is the ME_MS shown), positions 2, 3 ... by priority then ME_EC, Volume Type `Potential volume if sourced`. A line is included when any of its parts is in a selected subcategory, and then all its parts are shown.

Sheets: `Read me` (read-only; months are the build/shipment month with no lead-time offset; volumes from Y+2 are a yearly plan; "Potential volume if sourced" rows are not demand and must not be added; volumes are plans, not orders), `Our parts` (read-only: Category, Subcategory, Product, EMS, BOM ME_EC, Source Position, ME_EC, Manufacturer, MPN, Description, ME_MS, Volume Type, `Volume Y`..`Volume Y+10`, months `Y-01`..`Y+1-12`; monthly = sum over the `Product_Volumes` rows of the same Product ID (Series and Sample) of the month's units x `Qty Per Unit`, 0 when the product or month is missing; the same figures on every row of a line), `Your alternatives` (one row per distinct part; grey A-D locked, E-I open, all text, Yes/No list on F) and `Your pricing` (one row per distinct part plus 300 blank rows for proposed alternatives; grey A-C locked, D onward open; `Price Y`..`Price Y+4`; text except MOQ, Lead Time (weeks) and the price columns). Header rows are text on every sheet, so month headers stay `YYYY-MM`. Each protection gets the file owner as editor first, then every other editor and domain edit are removed; the file is moved into the folder last (a failed move trashes it: `Could not save the file in the Manufacturer files folder: <message>`). Errors the dialog shows: `Enter the manufacturer name.`, `Select at least one category.`, `No parts match the selection.`, `The selection is too large; select fewer categories.` (rows x columns above 2,000,000 cells). The file is not shared by the script: share it from Drive.
